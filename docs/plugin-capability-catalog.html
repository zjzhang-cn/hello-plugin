01Cordis 内核能力

任何插件（宿主/客户端）都有的基础上下文 API。详阅 vendor/cordis 与 docs/cordis-primer.md。

能力用法说明
插件导出export const name + export function apply(ctx)宿主半区标准形态
服务注入inject: ['svc']声明依赖，激活后 ctx.svc 可用
生命周期ctx.effect(cb, label)副作用放 effect，卸载自动回收
事件监听ctx.on(event, listener)监听 Cordis 事件
事件广播ctx.emit(event, ...args)触发事件（宿主端）
事件分发ctx.parallel / ctx.waterfall并行 / 串行分发模式
子插件ctx.plugin(Plugin, config)插件内再挂子插件
服务提供ctx.provide(name, value)向依赖方暴露自有服务
服务获取ctx.get(name) / ctx.inject([...], cb)读取 / 注入服务
日志ctx.logger('scope')带 scope 的日志器

03客户端核心服务 · 浏览器内

客户端插件运行在浏览器，apply(ctx) 在客户端 Cordis 容器里。核心是 ctx.remote 与 ctx.connection。

hostctx.remote

Typert 生成式 Remote：remote.<ns>.<method>() 调宿主；$on 收转发事件；$stream 流式；$mount 装载贡献。

hostctx.connection

浏览器↔宿主线缆：rpc.call(channel, endpoint, { args }) 调宿主。宿主端同名服务提供 rpc.handle。

bictx.slots

插槽系统：register({ name, id, inject }, Component) 注入 UI 组件。

clientctx.layout

布局：toggleSidebar / openDetails / closeDetails / attachPanels。

clientctx.theme / ctx.locale

主题与国际化。locale 提供 bind(ns) 翻译函数。

clientctx.settingsScope

设置作用域绑定：bind() / set() / unset() / mutate()。

clientUI 领域服务

uiSession / uiConversation / uiWorkspace / commandUi / modelDirectories / inputTriggers。

clientctx.clientModules

客户端模块系统（window.__ModuleLoader__ 的宿主面）。

corectx.timer

客户端定时器（cordis-client-runner）。

04双向通信通道

dsh 双面插件的核心。宿主与客户端隔着 HTTP + WebSocket，消息必须走封装通道。

通道方向机制关键 API
Unary RPC客户端 → 宿主POST /api/<endpoint>，payload { args }客户端 connection.rpc.call('/hello','ping',{args})；宿主 connection.rpc.handle('/hello', handler)
Typert Remote客户端 → 宿主生成式 descriptor，namespace/method 端点客户端 ctx.remote.<ns>.<method>()；宿主 @typert 标记 Service 方法
Remote events宿主 → 客户端ctx.emit → api-remotes 转发 → 网关广播 → 客户端 $on客户端 ctx.remote.$on(event)；宿主 ctx.emit(event)；事件名须进 allowlist
长轮询宿主 → 客户端复用 rpc.handle 通道挂起等待宿主 events/poll 端点 + 客户端循环（见 hello-plugin）
WebSocket mux双向/api/remote.mux，Typert streamctx.remote.$stream；connection.rpc.open（仅 worker 隧道）
Fetch 精确路由宿主 → 客户端rpc.fetch.register 注册 GET/HEAD 路由宿主提供浏览器原生响应

05插槽（Slots）与 UI 体系

客户端 UI 通过插槽组合。shell.overlay 是叠加槽（hello-plugin 用它）；root 是渲染树根（不要注册）。

// slots.register 的 inject 业务面：把 ctx 里的服务传给组件
// 组件直接传（非 () => createElement(...)），否则注入 props 落不到组件上
// 组件永不引用模块级 ctx —— 服务只从 props 来
// 渲染器展开为 <Comp {...injected} />
// 悬浮小组件挂 shell.overlay（list 槽，叠加式）
ctx.effect(() => slots.inject('shell.overlay', () => slots.register(
  { name: 'shell.overlay', id: 'my-widget', inject: () => ({ connection: ctx.connection }) },
  Comp,
)))

06工具（Tools）贡献

插件通过 ctx.tools.register(definition) 贡献模型可见工具。工具定义含 name / description / JSON-Schema parameters，模型经系统提示词组装看到。全目录见 docs/tool-catalog.md。

ctx.tools.schemas() 返回当前可用工具 schema 白名单（只含 name/description/parameters，永不外泄实现）。示例工具：bash、edit/read/write、subagent、job_*、lsp、skill、schedule_* 等。

07关键约束（踩过的坑）

/api 独占：共享通道只允许一个 interceptor（api-gateway 占用）→ 自定义通道另开如 /hello。
Remote events 单例：registerRemoteEvents 已被 api-remotes 占用 → 自定义事件用长轮询。
allowlist 限制：自定义事件名无法进 API_REMOTE_FORWARDED_EVENTS（除非改 harness）。
load id 必须等于包名：window.__ModuleLoader__.load({ id }) 的 id 是图行 id。
浏览器 rpc 无 open：自建 rpc.handle 通道是请求-响应；流式 open 只在 worker 隧道。
长轮询要点：广播语义、超时兜底、abort 清理。
